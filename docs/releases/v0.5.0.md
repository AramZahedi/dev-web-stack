# devstack v0.5.0

**Release date:** 2026-11-03

devstack 0.5.0 is a follow-up to 0.4.0 with a real HTTP benchmark request
builder, selectable load engines, readable site configuration paths, and fixes
for the benchmark modal and stale host-tuning restart state.

> **Local development only.** devstack is not a production hosting platform. Do
> not expose its dashboard, daemon, services, or ports to the internet.

## Highlights

### HTTP benchmarks

- Added a request builder for benchmarks: method, path, headers, and an optional
  JSON body, with a live target URL preview.
- Added a selectable engine:
  - **`fasthttp`** (default) for HTTP/1.1 throughput.
  - **`net/http`** when the target negotiates HTTP/2.
- Results record the engine, tool, method, path, header names, body size, target,
  and measured latency/RPS. Header values and request bodies are never stored.
- The form is now two aligned rows. Headers and JSON body are hidden behind an
  **Advanced** toggle.
- The result modal is viewport-fixed, locks page scrolling, and scrolls only its
  own body. Mouse-wheel and middle-button scrolling over the modal no longer move
  the underlying page.

The `fasthttp` engine uses the same HTTP stack as bombardier without its
Host-header limitation. Bombardier itself was evaluated and not adopted because
it is a CLI `main` package, its fasthttp mode cannot set the custom Host header
devstack needs for local vhost routing, and its net/http fallback was slower than
the built-in generator in a loopback comparison.

### Readable site configuration names

- Generated PHP/FPM configuration directories now use the unique site name:
  `~/.devstack/sites/<site>` and `/data/devstack/sites/<site>`.
- Generated nginx/Apache vhosts now use the site name:
  `<site>.conf`.
- Legacy ID-based configuration directories migrate on the next prepare/start.
  Orphaned legacy directories are archived under `sites/_orphaned` instead of
  being deleted.
- The opaque site ID remains the stable internal key for the database, API,
  ports, certificates, logs, and process tracking.

### Host-tuning restart correctness

- The Windows helper records the requested `TcpTimedWaitDelay` and clears the
  **Restart required** marker once Windows has actually rebooted.
- Re-applying the same active profile after a reboot no longer re-arms the
  Windows restart marker.
- The WSL agent reports the VM boot time; the WSL-VM restart marker clears only
  after the VM has actually restarted following a `.wslconfig` change.
- Re-applying an identical `.wslconfig` no longer moves its apply timestamp or
  re-arms the WSL-VM marker.

### Reliability fixes

- A stopped site with a build profile no longer receives stale build focus.
- Benchmark configuration and vhost migration preserve existing data and never
  overwrite a name-based directory.

## Install

### Windows

Run `devstack-installer.exe` (or `devstack-setup.exe`) and follow the UAC and
install prompts. Or extract the Windows ZIP and run `.\install.ps1` from an
elevated PowerShell.

Then verify:

```powershell
devstack version
devstack doctor
```

### Linux

```sh
tar -xzf devstack_0.5.0_linux_amd64.tar.gz
cd devstack_0.5.0_linux_amd64
./install.sh
devstack init
```

Or:

```sh
./install.sh --release 0.5.0
devstack init
```

## Upgrade

- Windows: run the new installer with `-Upgrade` / `--upgrade`.
- Linux: `./install.sh --upgrade --release 0.5.0`.

Windows upgrades back up binaries and `/data/devstack` and roll back on failure.
Linux migrations take a SQLite snapshot before the first pending migration.
Existing site configuration folders and ID-named vhosts migrate automatically;
the old vhost files are removed when the owning web provider next syncs.

## Known issues

See [`docs/known-issues.md`](../known-issues.md) for the current list. The most
important release caveats are:

- Windows VM/multi-machine acceptance is not complete beyond the tested host.
- Database E2E cycles 9–15 are paused.
- Host tuning is machine-wide and `.wslconfig` changes need a WSL restart.
- Defender exclusions are skipped when the Defender module is unavailable.
- Releases are unsigned.
- GitHub workflows are manual-dispatch only.

## Security

devstack is local-only. Do not expose the dashboard, daemon, services, helper
pipe, or local CA to untrusted users or the internet. See
[`docs/known-issues.md`](../known-issues.md) and the security section of the
[README](../../README.md) before changing any network or firewall settings.
