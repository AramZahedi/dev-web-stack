# devstack v0.4.0

**Release date:** 2026-11-03

devstack 0.4.0 completes the Windows + WSL2 serving path, adds automatic
nginx/Apache switching and Built-in fallback, and brings the same performance
tuning profiles to Windows, WSL, the WSL VM, and Linux services.

> **Local development only.** devstack is not a production hosting platform. Do
> not expose its dashboard, daemon, services, or ports to the internet.

## Highlights

### Windows Docker serving

- Managed nginx and Apache containers now serve Windows/WSL sites privately on
  `127.0.0.1:18080` while the Windows daemon keeps public ports 80/443 and
  terminates TLS.
- WSL static sites route through the managed Docker web server.
- Windows-source static sites stay on the daemon's supervised direct route.
- New and changed site vhosts are validated and gracefully reloaded without
  restarting the web container.
- The full generated-vhost renderer is used for private HTTP vhosts.

### Automatic web-server switching

- Direct `nginx ↔ Apache` switching works without a Built-in round trip.
- Failed switches roll back to the previous server.
- Deactivating or uninstalling the active web service automatically returns
  serving to `builtin` before the container stops.
- The dashboard disables nginx/Apache choices when that service is not
  installed, and keeps them available if the service list cannot be read.
- Switching Docker → Built-in starts WSL static backends and publishes their
  routes; switching back restores the Docker route.

### Cross-platform performance tuning

- **Balanced**, **Throughput**, and **Custom** profiles.
- **Throughput is the default**.
- Applies to:
  - managed service containers,
  - WSL sysctl/limits,
  - WSL VM memory/processors/swap through `.wslconfig`,
  - Windows power plan, TCP ports, registry, NTFS, and optional Defender
    exclusions.
- Combine host tuning with any profile.
- Preserve the original pre-devstack tuning baseline across profile switches.
- `Reset` restores the baseline and removes managed files.
- Defender exclusions are best-effort when the Defender module is unavailable.

### Reliability fixes

- A stale static site with a missing project path or missing agent backend no
  longer blocks a serving switch, site stop, or site delete.
- Site-driven vhost syncs reload the running web container.
- Built-in route publication happens after static backend ports are allocated.
- Windows test port allocation avoids the reserved site-backend range.
- phpMyAdmin keeps its private, short-lived, single-use signed dashboard signon.

## Install

### Windows

Run `devstack-installer.exe` (or `devstack-setup.exe`) and follow the UAC and
install prompts. Or extract the Windows ZIP and run `.\install.ps1` from an
elevated PowerShell.

Then verify:

```powershell
devstack version
devstack doctor
```

### Linux

```sh
tar -xzf devstack_0.4.0_linux_amd64.tar.gz
cd devstack_0.4.0_linux_amd64
./install.sh
devstack init
```

Or:

```sh
./install.sh --release 0.4.0
devstack init
```

## Upgrade

- Windows: run the new installer with `-Upgrade` / `--upgrade`.
- Linux: `./install.sh --upgrade --release 0.4.0`.

Windows upgrades back up binaries and `/data/devstack` and roll back on failure.
Linux migrations take a SQLite snapshot before the first pending migration.

## Known issues

See [`docs/known-issues.md`](../known-issues.md) for the current list. The most
important release caveats are:

- Windows VM/multi-machine acceptance is not complete beyond the tested host.
- Database E2E cycles 9–15 were paused.
- Host tuning is machine-wide and `.wslconfig` changes need a WSL restart.
- Defender exclusions are skipped when the Defender module is unavailable.
- Releases are unsigned.
- GitHub workflows are manual-dispatch only.

## Security

devstack is local-only. Do not expose the dashboard, daemon, services, helper
pipe, or local CA to untrusted users or the internet. See
[`docs/known-issues.md`](../known-issues.md) and the security section of the
[README](../../README.md) before changing any network or firewall settings.
