## 3. Release commands

The release path is real but **unpublished**:

```sh
# Build an unsigned local archive and checksums.
make release VERSION=0.2.0

# Verify the archive contract, checksum, members, and packaged version.
make release-test

# Inspect the result.
ls -l dist/release/devstack_0.2.0_linux_amd64.tar.gz dist/release/checksums.txt
sha256sum -c dist/release/checksums.txt

# Install a published release (works after a real tag/release exists).
./install.sh --release 0.2.0
devstack init

# Install a local archive without the network.
./install.sh \
  --archive dist/release/devstack_0.2.0_linux_amd64.tar.gz \
  --checksums dist/release/checksums.txt
devstack init
```

`install.sh` runs as the normal user and uses `sudo` only for the helper
binary/config/unit. It installs no packages, does not configure nginx/Apache,
and does not run `devstack init` automatically. Release archives are unsigned;
the SHA-256 manifest detects corruption/tampering, not a compromised host.
Linux x86_64 only. No agent, Windows, macOS, or arm64 member exists.

The tag-driven release workflow is `.github/workflows/release.yml`; version
tags are `v<major>.<minor>.<patch>`. `goreleaser check` is configured in that
workflow but has not been observed running in CI here.

## 4. Upgrade and recovery commands

```sh
# Published release.
./install.sh --upgrade --release 0.2.0

# Local archive.
./install.sh --upgrade \
  --archive devstack_0.2.0_linux_amd64.tar.gz \
  --checksums checksums.txt

# Source checkout.
make build
./install.sh --upgrade

# Preview without writing.
./install.sh --upgrade --dry-run --release 0.2.0

# Required follow-up.
devstack init
devstack doctor
devstack doctor --json
```

- `--upgrade` requires an existing `~/.local/bin/devstack`.
- It stops the user daemon before replacing binaries and aborts if the stop
  fails.
- It keeps `/etc/devstack/helper.yaml` unless `--force-config` is passed.
- Before applying pending migrations to an existing database, the store writes
  a consistent `VACUUM INTO` backup under
  `${DEVSTACK_HOME:-~/.devstack}/backups/state.db.pre-migrate-<UTC timestamp>.bak`.
  It keeps the three newest backups and applies no migration if the backup
  fails. A fresh database skips the backup.
- Downgrades are unsupported. Restore a pre-migration backup only as a
  deliberate recovery operation with the daemon stopped.
- M1 has no auto-update, self-update, diagnostics bundle, or remote catalog.
  `devstack doctor --json` plus service logs is the support surface.
