## Defects found and fixed during this E2E pass

Earlier rounds (already committed in this branch) fixed Node site runtime
support, `PHPExec` staging, WSL argv path translation, stopped-site status,
static build document roots, unprepared Windows builds, source-copy wiring,
Node in-use removal checks, idempotent start, empty dashboard logs, HTTPS
benchmark targets, and root-execution documentation.

This run found and fixed:

1. **Terminal and exec sessions did not expose the site runtimes.** The agent
   built the CA environment but never prepended the selected PHP/Node build
   directories to `PATH`, so `php`/`node` were “command not found” despite the
   UI copy. Added `Runtime.sitePathEnv` and applied it to the terminal and
   `ExecSite`; added `TestSitePathEnvPrependsRuntimeShims`. Verified live:
   `PHP 8.4.27` at `/data/devstack/runtimes/php@8.4.27-r1/bin/php`, Node
   `v24.22.1`, npm `11.19.1`.
2. **The dashboard had no source-mode change action.** The API/CLI supported
   verified copies, but site detail only displayed the mode. Added
   `changeSiteSource` to the UI client and mock, a stopped-site-gated “Project
   source” section with destination validation, and two SiteDetail tests.
   Verified both directions live with SHA-256 equality and route republish.
3. **Service installs failed entirely when the registry was unreachable,** even
   when the exact digest-pinned image was already local. `agentdocker.Install`
   now accepts a local image only after `docker image inspect <repo:tag@digest>`
   succeeds; added a regression test. MySQL then installed offline from the
   cached digest.
4. **Windows CLI `exec`/`shell`/`shell-init` pointed at a site shim directory
   that is never created.** `WindowsSiteEnvironment` hardcoded
   `/data/devstack/tools/sites/<name>/bin` with no runtime bins, so `exec` failed
   with `php: not found`. It now includes the site's exact PHP/Node build bins
   (and the build-profile Node line) before the conventional shim directory;
   added a regression test.
5. **Agent backend ports can collide with Linux ephemeral ports.** Added a
   short `EADDRINUSE` retry around the loopback bind, with a portable Windows
   error check for the native test run, and a retry regression test. This also
   removes the intermittent WSL suite failure.

## Blocked / not reproducible here

- Native Windows `go test -race`: requires CGO; not available in this toolchain.
- Clean-machine install, real reboot/resume, populated-data upgrade/rollback,
  Windows 10 22H2, and multi-user/SID isolation.
- Root execution inside the managed WSL distro is architectural: the agent,
  PHP-FPM/Node workers, builds, and terminals run as root (`R2-M12`/`R4-H1`
  residual). Documentation now states this explicitly.
- Provider-switch vs activation interleaving (`A-2`) still needs a cross-package
  lifecycle coordinator.
- WSL `/api/v1/fs` allows browsing arbitrary absolute paths and `../../etc`
  directory listings; not confined to project/home roots. Documented security
  residual.
- Node runtime in-use errors still name PHP in the remediation text (message
  only).
- Doctor warns when a compiled-in PHP `extension_dir` points at a nonexistent
  `/tmp` path.
- Service config reset JSON reports an empty hash/size even though the content
  is restored.
- A freshly started site on a new WSL backend port can return one 502 while WSL
  localhost forwarding catches up (observed 19 ms after start); a retry
  succeeds.

## Reproduction notes

- Use a dedicated home, e.g. `%TEMP%\opencode\e2e-home`, and ports 7070/8080/8443.
- Recover the dashboard token with `devstack ui --home <home> --json`; open the
  `#token=` URL, then authenticate with `X-Devstack-Token`, fetch
  `/api/v1/session`, and send `X-CSRF-Token` on mutations.
- The agent binary must be replaced atomically while
  `devstack-agent.service` is stopped; restart it and wait for reconcile.
- Run the WSL Go suite as an unprivileged user; the tooling/root checks and
  vhost traversal validation intentionally behave differently as root.

# Post-E2E hardening (2026-10-30)

The residuals listed above were addressed where code changes could do so:

| Residual | Change | Verification |
| --- | --- | --- |
| WSL `/api/v1/fs` browsed arbitrary paths | Agent now confines browsing to `<root>/projects` after lexical and resolved-symlink containment; the API rejects relative paths, NULs, and `..` segments before calling the agent. | Agent/API regression tests; live `projects=200`, `traversal=400`, `/etc=400`, `secrets=400`, Windows-outside=403 |
| A-2 provider-switch/activation interleaving | `sites.SetServingMode` now takes the service manager's lifecycle mutex before `sites.mu`; activation already takes the same mutex and then calls into sites, giving one lock order. | `TestActivationHoldsLifecycleMutex`, `TestSetServingModeTakesSharedLifecycleLock`, full `-race` suite |
| Node in-use message said “PHP runtime” | `RuntimeInUseError` derives “Node runtime”, “PHP runtime”, or “runtime” from the build ID; CLI remediation is provider-neutral. | `TestRuntimeInUseErrorMessageNamesTheRuntimeKind` |
| Service config reset JSON omitted hash/size | Agent-backed reset reads the restored content back and reports its hash and byte size; read-back failure is non-fatal with a message. | `TestConfigServiceWithAgent` |
| WSL forwarding 502 after a new backend port | Host-side readiness probe after start plus a bounded proxy retry window (20 × 75 ms) for bodyless requests on connection refused. | `TestWaitBackendReady*`, `TestRetryTransport*`; live first request after a fresh add returned 200 (~349 ms total) |
| Doctor warned about compiled-in `/tmp` extension_dir | New PHP installs rewrite the build base `etc/php.ini` to the final installed extension directory before registration. The existing live build was patched the same way. | `TestEnsurePHPBaseIniWritesCompensatingExtensionDir` |
| Final-tree race coverage | Full WSL suite under `-race` with `-p 1` as an unprivileged user. | 60 packages, exit 0, 0 `DATA RACE` |
| No coverage baseline | Full WSL coverage profile. | 73.9% statement coverage; lowest packages: `cmd/php-smoke` 24.3%, `cmd/devstack-installer` 34.0%, `internal/agentclient` 45.3%, `internal/helperclient` 46.0% |

Remaining residuals after this pass:

- Root execution inside the managed WSL distro is architectural.
- Clean-machine install, real reboot/resume, populated-data upgrade/rollback,
  Windows 10 22H2, and multi-user/SID E2E still require dedicated machines.
- No independent security review or fuzzing campaign; coverage is 73.9%, not
  100%.
- A one-request victim of a longer WSL forwarding outage can still receive a
  502 after the 1.5 s retry window; a retry succeeds.
